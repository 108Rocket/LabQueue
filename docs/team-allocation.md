# LabQueue 四人任务分工方案

## 依据与当前状态

本方案依据课程讲义第 31–39 页、`docs/course-requirements.md` 和当前产品简报制定。用户已明确：小组四人，108Rocket 与 Vamsinger 为主要负责人，希望承担更多任务；另两人暂称组员 A、组员 B。

作业仅通过 GitHub 仓库交付。不汇报、不录屏、不做实验 B，保留实验 A。

下列具体职责是建议采用的执行分工，不代表成员已评审、任务已完成或课程 M1/M2 已通过。尚未获知个人技能和可投入时长，先按职责完整性安排；评审时可调整负责人，但需保留交接记录。周次按课程实际安排，不自行推算日历日期。

## 业务实现范围与协作边界

这是后续架构和故事分配的责任方向，不提前确定数据库、认证方案或执行器实现。M1/M2 通过后按正式故事开展功能实施。

| 成员 | 负责范围 | 需要交接的接口或证据 |
| --- | --- | --- |
| Vamsinger | 任务提交/查询/取消的业务规则，用户与组关系的业务授权，任务状态展示所需接口，首版跨组全局 FIFO 的排序规则 | 与 108Rocket 共同约定身份契约和状态机；输出候选任务选择规则；向 A 提供字段、错误码、状态语义 |
| 108Rocket | 数据模型与事务边界，GPU 租约与原子领取，监测新鲜度和外部占用，绑定用户身份的执行机制，心跳/取消确认/故障恢复，部署集成 | 向 Vamsinger 提供资源状态和受控的领取/执行接口；向 A 提供可展示状态；向 B 提供可控的模拟器或测试替身 |
| 组员 A | 任务提交表单、队列/任务详情页面、可观察资源状态、等待/监测异常/执行失败的反馈、与权限相关的界面状态 | 用约定接口联调，补充页面和端到端验收；公开看板不暴露他人的命令与日志；界面隐藏不能代替后端授权 |
| 组员 B | 自动化验收与回归脚本，并发重复领取、越权取消、监测失效/过期、恢复与重试等用例，PRD 确认后的性能测试与证据 | 提供可复现的输入、环境、预期和结果；区分模拟验证与真实服务器证据，维护 FR/NFR—测试对应关系 |

Vamsinger 的调度策略选择“下一个候选任务”，108Rocket 的资源事务机制决定“能否安全领取并执行”；业务层不得绕过资源机制直接分配 GPU。取消请求的身份和业务校验由 Vamsinger 主责，执行侧停止与最终状态确认由 108Rocket 主责，二人共同评审取消与启动竞态。

每位开发者为自己的功能编写必要测试；B 负责独立检查和证据完整性。108Rocket 与 Vamsinger 相互复核核心变更；A 的业务交互由 Vamsinger 复核；B 的测试断言和统计口径由 108Rocket 复核。核心并发与权限用例由 B 独立验证。

至少 3 个 Epic、12 个 Story 是全组要求，具体故事在架构之后按复杂度和预计投入分配，不机械按人数均分。A 负责完整的用户交互故事或其中明确的界面任务；B 的自动化测试代码、测试替身和实验工作作为有负责人、有验收条件的任务，关联到对应故事与 NFR。不得为凑数量将文档排版或重复测试包装成用户故事。

## 实验 A：规划深度对照

- **Vamsinger 是两条路径的同一操作人**：在同一天、同宿主、同模型下，分别完成 X（完整上游产物）与 Y（干净会话中只描述需求）。不能让两位负责人各做一条路径。
- **B 负责实验组织与取证**：记录环境、版本、输入、会话和五项指标，保留相同 code-review 标准；作为观察记录者不向某一路径额外提供实现帮助。
- **108Rocket 复核方法与结论**：实验前检查 X/Y 难度是否相当、输入隔离和统计口径；实验后核对架构冲突、规则违规及规划投入。A 可核对涉及界面的共同验收结果。
- 统计平均单故事会话轮数、首次评审通过率、项目规则违规次数、ADR 冲突次数、完成后返工故事数；记录分母和单位。正结果、无收益和负结果都如实写入复盘。

## 日常协作与评分证据

1. 每个故事记录实现负责人、复核人、需求依据、验收标准及测试证据。状态随真实工作推进，人工验收后才标记 done。
2. 每个 BMAD 工作流使用新会话。人类成员可调用多个 AI 角色，产品/架构职责不限制技能使用。
3. 各自记录参与的真实决策，Vamsinger 定期检查全组是否覆盖课程的 ≥15 条决策、≥5 条否决/实质修改要求。该要求是全组累计，不分配固定否决次数，不在事后补造。
4. B 维护 FR/NFR—ADR—Story—测试的对应检查，Vamsinger 和 108Rocket 负责修正各自的上游产物；每周随机抽 2 条需求演练追溯。
5. 每周进行一次短的进度与风险核对，每次阶段验收前检查范围、依赖、测试和证据。阻塞及时同步给两位主要负责人，减少两人集中承担最后集成的压力。
6. 全员记录实际 AI 工具、模型/版本、使用日期与用途，并保存适当的对话证据；对外材料隐藏账号、私密命令和密钥。
7. 两位主要负责人同时承担工程实现和管理判断。A、B 的验收与证据工作贯穿两轮迭代。评分依据见[课程要求](course-requirements.md)。

## 现在即可开始的任务

交付证据以实际完成和验证的成果为准，模拟验收记录应明确标注。真实姓名、学号、组长登记身份和课程实际日期由团队补齐。

- Vamsinger：整理简报待确认问题，和真实使用者确定首版范围；启动产品简报与 PRD 工作流。
- 108Rocket：核对当前机器的环境可复现性，列出执行身份、观测权限和租约一致性的待决策问题，为 M1 提供技术约束。
- 组员 A：绘制提交—等待—运行—完成/失败的用户流程及页面草图，记录取消和监测异常时用户需要看到什么。
- 组员 B：将候选 NFR 转成“环境、输入、预期、测量方式”的检查表，复核重复租约与监测失效两类候选验收指标。
