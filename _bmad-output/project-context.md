### 实现规则

1. **事务权威（AD-1）** 由应用服务在本机 SQLite 管理关键状态和事件，核验 WAL 与 `synchronous=FULL` 生效。先 `BEGIN IMMEDIATE` 再读取前置条件，提交后才报告成功。忙锁从事务起点重读，已知未提交的开放事务先回滚。提交结果不明时停用该连接，从新连接的已提交快照核对，核实前不重放启动或释放。外部探测与 RPC 放在事务外。
2. **持久全局 FIFO（FR-02、AD-2、Story 1.1–1.2）** 同一入队事务递增持久全局计数器并写入唯一 `enqueue_seq`。入队以提交确认，排序只看序号，跨组、同时间、墙钟回拨和回执乱序均保持顺序。重启保留计数器，删除任务不复用序号。相同所有者和幂等键重放同内容返回原结果，同键异内容拒绝。本人队位在同一快照内按仍排队且序号更小的任务数加一计算。确认时间用 UTC 存储，展示时明确时区。
   - **页面快照版本（D-011、Story 1.2/3.2/4.2）** 服务端在同一数据库持久化独立于 `enqueue_seq` 的全局单调版本。凡改变任务状态、全局队位、等待原因、取消资格或取消请求结果的写入，均须同事务推进版本，即使本人任务状态未变。列表、详情和取消回执使用同一版本域，响应版本与内容取自同一已提交快照。列表和详情在同一登录会话共享已见版本下限，刷新、切页或重开仍适用。缺少可比较版本或低于下限的响应不得更新页面或重开取消入口。仅含取消结果的回执按请求 ID 核对，不得替换、清空或拼成完整页面快照。任一响应提高下限时，低于下限的缓存仅标「上次确认」，待取得不低于下限的完整快照再更新页面。较新的完整回队快照应更新为排队中，显示重算的当前队位、等待原因和取消资格。
3. **领取与租约同提交（FR-04/05、AD-3、Story 2.2）** 领取事务重查队首、回队优先条件和最新准入状态，只选择观测可用且无当前租约的卡。将全新领取 ID、GPU UUID、准入代际、当前租约和任务已获准状态一起提交。数据库分别对当前租约的 GPU UUID 和任务 ID 强制唯一，记下领取和释放事件。用稳定 UUID 标识卡，数字卡号仅作探测索引。未知显存保持未知，可申请一张完整卡的使用权，每卡最多一个平台任务。
4. **观测失效阻断准入（FR-03/04、AD-5、Story 2.1/4.1、D-006）** 观测快照须完整覆盖两张配置卡，拒绝乱序或旧发布者样本。漏报、失败、过期或外部占用不明时全局停止新领取和未确认启动，进入阻断与推进准入代际同提交。单卡证实被外部占用时，同提交撤销该卡未确认领取的启动资格。重启先推进代际再接受新观测。新快照不能恢复旧领取资格。本人查询须显示对应等待原因。
5. **启动与观测到期按提交顺序裁决（AD-4/5、Story 2.3/4.1、D-006）** 在写事务内单调推进权威模拟时钟，达到从采集开始计算的截止点时，同提交标记观测过期并推进代际。启动取得写权后复核时钟、最新观测、单卡资格、当前领取和租约、执行身份及未取消、未待核对、未确认且未启动的证据。启动确认与按任务 ID 唯一的模拟启动事件同提交。过期先提交则新增确认和启动均为 `0`，启动先提交则保留原启动及租约。持续时长和心跳用单调时基。
6. **取消与启动按提交顺序裁决（FR-07、AD-4/6、Story 3.1–3.3、D-005、D-010）** 在同一写事务规则下核验本人及持久启动证据。证实未确认且未启动时，取消裁决先提交即置为已取消、出队并封闭已有领取、解除对应原租约，随后启动数为 `0`。已证实启动确认先提交时，即使回执丢失也返回已过截止点，保留租约。确认事实未知时持久记录执行待核对，本次未取消。受理提交不抢占裁决。每次完成裁决时同提交持久记录原请求 ID 的终局结果，释放至多一次。
   - **核对与封存** 按可信所有者、任务 ID 和取消请求 ID 核对持久结果。已提交受理且未终结才是「处理中」，重启后由服务端按当前持久证据继续裁决原 ID。普通刷新只读，仅凭超时、查无记录或无法核实仍视为「未知」。封存须由本人主动发起幂等命令「核对并封存旧取消请求」。服务端校验所有权后，在与受理互斥的写事务内复查并持久封存未受理的旧 ID。若受理先提交则返回已知事实。受理或推进取消前在写事务内检查 ID 未封存且未终结。终局和封存记录跨重启保留，旧请求仍可能到达期间不得删除。迟到的已终结或已封存请求只读，不得改变请求记录、任务、租约、取消事件或快照版本。
   - **恢复取消入口** 列表和详情在同一登录会话共享当前待核对的请求 ID，刷新、切页或重开时继续核对。回执只用于匹配的 ID，旧回执不得解除新请求的待核对或降级已知终局。只有符合规则 2 的同一完整已提交快照同时证明该 ID 已终结或已封存、本人任务仍可取消时，才恢复入口。结果未知时入口保持关闭，允许本人主动核对，禁止自动重发取消。再次取消须由本人主动使用新 ID，服务端按当前持久证据重新裁决。页面只在服务端确认取消已提交后显示「已取消」。页面呈现与交互细节待 UX 对齐。
7. **待核对保留原卡（FR-05、AD-4/6、Story 3.3/4.4、D-005/007）** 心跳超时只触发核对。执行证据须匹配任务、领取 ID 与 GPU UUID。结果仍未知时，即使租约已超时且观测显示空闲，原卡解除保留、原卡新增派发及任务新增启动均为 `0`。只恢复已确认启动的证据、尚无终态证据时，仍保留原卡且不得回队。待核对记录提交失败时保持准入关闭，补记持久成功或持久封闭旧领取后方可恢复准入。
8. **封闭旧领取并原序回队（FR-02/04/05/07、AD-5/6、Story 4.2/4.5、D-006/007）** 恢复事务在取得写权后重读任务、租约和启动证据。任务仍已获准且匹配当前领取及原卡，领取已失效或待核对，并证实未确认、未启动且未取消时，才同提交封闭并撤销旧领取、解除原租约一次、按原 `enqueue_seq` 回队。待核对分支即使观测和代际一直有效也须如此处理。取消先提交或领取已变更时，迟到的恢复写入数为 `0`。
9. **回队优先与拒绝旧请求（AD-2/3/5/6、Story 4.2–4.3、D-006/007）** 领取事务从持久证据检查是否有较早且已核实应回队的任务。若有，即使另有可用卡也不得为后到任务发租约，先恢复早到任务再重取队首。证据未知的任务继续保留原卡。回队后按最新有效观测重新领取，可换卡，同卡同身份也须发全新领取 ID。旧领取在保留原租约期间不能新增启动确认或启动。重领后，旧领取的启动、心跳、结果、释放和恢复请求不得改写任务、新租约及其变更历史。
10. **终态与释放同提交（FR-06、AD-6、Story 2.4）** 确认当前执行已结束且不会再使用原卡后，同提交记录完成或失败并解除租约。OOM 记录失败和本人可见的诊断，保留原参数，禁止自动调小 batch、探测训练或重跑。
11. **服务端校验所有权（FR-01/08、AD-7、Story 1.1/1.3）** 会话与可信组映射决定所有者及组。列表、详情、取消和私有输出校验所有权，取消在写事务内复核。拒绝匿名及同组或异组非本人访问，客户端字段不能授权。命令、路径、环境变量和日志仅通过授权入口向本人提供，私有输出走服务端分配的引用，公共看板仅用汇总数据。Cookie 写请求须校验跨站请求凭证。

### 模拟验收与证据

12. **按提交状态取证（NFR-01/02、D-008）** GATE-01 至 GATE-04 全部通过且两项 NFR 达标才算模拟验收通过。用事务暂停点安排竞态，从已提交状态、启动事件和租约历史验证重复启动、同卡租约重叠、已取消任务启动均为 `0`。负向权限用例验证越权成功、私有测试标记泄露、未经授权的状态变更均为 `0`。本地启动检查仅提供环境证据。
13. **按 Story 依赖联调（D-008）** Story 1.2 的单卡释放后 FIFO 等 2.2 可用后联调，Story 1.3 的实际本人取消正向对照等 3.1 和 3.2 可用后联调。Story 4.6 复用前置功能，仅收集跨重启故障注入、重放和 NFR-01 综合证据。

首版采用全局 FIFO。组间与组内公平、组权重、长任务记账及闲置借用规则留待后续 PRD/ADR 评审。平台外占用可能变化，避免承诺固定等待时长。

## 真实 L20 条件目标

- **默认关闭（FR-09、AD-8、AC-12）** 模拟验收独立进行。真实派发启用前须完成架构评审，在目标服务器以普通权限核验两卡 UUID、外部占用可见性、观测有效期、账号与 UID 绑定、代理凭证、启动／取消边界及故障恢复。真实配置、数据目录与凭证单独管理，启用前核对未决执行和 GPU 保留，通过前置验证后才做受控任务验收。
- **本人执行与平台内租约** 每用户代理必须以提交者本人 Linux UID 运行。共享后端不得代执行，不依赖管理员权限或切换他人身份。在线启动裁决校验领取、观测和外部占用，禁止可重复消费或延后兑现的启动许可。监测失败、过期或外部占用不明时新增真实派发为 `0`，界面显示不确定性。租约只约束平台合作任务，禁止终止外部进程。平台运行中终止另行评审，核验权限、执行器和进程归属并防止 PID 复用误判。
- **真实执行证据** 核对启动与进程创建之间的故障窗。结果不明时保留原卡并核对，禁止重放启动。采样显存峰值记录时间、间隔和配置指纹，可漏峰。模型、batch、输入形状或精度改变后，旧估算失效。
