## 实现规则

1. GPU 使用稳定 UUID 标识；数字卡号是一次探测的索引，不能作为长期唯一身份。
2. 未知显存是独立状态，不能转换成 0 MiB 或“可共享”。初期一卡一个平台任务。
3. 普通用户无法强制隔离 GPU。平台独占仅指内部调度约定，必须显示外部占用的不确定性。
4. 外部 PID 的归属或占用读不全、NVML 报错、数据过期时，阻止新真实分配；不能以空结果等同空闲。
5. 观测到的显存峰值带采样间隔、配置指纹和时间；更改模型、batch、输入形状或精度后不能沿用旧估算。采样可能漏峰值。
6. OOM 只记录诊断和失败状态。自动缩 batch、启动探测训练或无提示重跑均需另行明确设计与用户授权。
7. 领取任务、获得 GPU 租约和更新状态要有事务及唯一性保证；多实例、重试或取消并发不能启动同一任务两次。
8. 用心跳、租约和启动确认区分“未知”“失败”和“空闲”；进程状态未查清时不能把租约超时当成 GPU 已释放。
9. 后端从可信身份获取 owner 与组关系。请求体里的用户/组字段不具有授权效力。
10. 任务命令、工作目录、环境变量和日志默认仅本人及明确授权角色可见。公共看板只展示必要排队元数据。
11. 普通服务账户不能切换为其他研究生的 Linux 身份。执行器必须明确绑定用户，不集中执行所有人的任意命令。
12. 不 kill 外部任务；平台任务的取消也必须核验身份、执行器和进程归属，避免 PID 重用导致误杀。
13. 组间公平与组内公平分别定义。组权重、长任务记账和借用闲置资源的规则必须在 PRD/ADR 中明确后实现。
14. 存储时间用 UTC，界面展示明确时区；持续时长与心跳用适当的单调时钟，不能直接用墙钟差保证租约安全。
15. 本地开发绑定 `127.0.0.1`。当前没有任务执行/提交 API，健康接口必须如实表示 GPU 监测尚未实现。
16. 课程产物状态按真实工作推进；文件存在或通过本地启动检查不能代替 M1/M2、NFR 或真实 GPU 验证。

## 必须在架构工作流做出取舍的事项

代理/执行身份；数据库与并发租约；外部占用检测及冲突恢复；公平算法；未知显存和 OOM；认证/隐私。每条正式 ADR 至少列出一个被否决方案、理由和需求依据。
