## Foundation · 基础

面向不同研究组研究生的中文版内部桌面 Web，提供已认证提交者的三页操作。M3 设计以两张模拟卡和预置合成账号为范围，真实 L20 派发仍关闭，启用受 FR-09 / AC-12 约束。视觉规则见 [DESIGN.md](DESIGN.md)。低保真参考见 [wireframes.md](wireframes.md)，出现差异时以 DESIGN.md 和本文件为准。

## Information Architecture · 信息架构

| 页面 | 入口 | 用户在此完成的任务 |
| --- | --- | --- |
| 提交任务 | 顶部导航、本人列表空态 | 填写自己的任务及显存估计。确认入队后进入我的任务或打开该任务详情。 |
| 我的任务 | 顶部导航、提交结果、详情返回 | 浏览本人的任务，核对队位、等待原因及当前状态，打开本人任务详情。 |
| 任务详情 | 本人任务行、提交确认后的详情链接 | 查看当前状态、失败原因和自己的任务配置，按取消资格操作。 |

`[ASSUMPTION]` 我的任务以便于回查为目的，示例将本人最近确认入队的任务置顶。实际队位读自最近一次确认的全局队列，从第 1 位起，只对仍在队列中的本人任务显示。调度顺序由确认入队序号决定。时间戳只供阅读，统一标出时区（示例用 UTC+08:00）。同时间、时钟回拨和重启均以 PRD 的入队顺序语义为准。FR-02、FR-03 / AC-01、AC-02、AC-10、AC-13。

| 已确认取消事务成功提交 | 「已取消」。 |

## Component Patterns · 组件行为

| 组件 | 行为 |
| --- | --- |
| 顶部导航 | 两个入口依次为「提交任务」「我的任务」。详情页可返回我的任务。 |
| 任务表单 | `[ASSUMPTION]` 模拟首版填写任务名与执行命令，命令作为任务数据。显存可选「未知」或填写正数估计，单位为 GiB，未知值独立保存。字段错误时可保留当前表单里的输入。FR-01 / AC-01、AC-02。 |
| 反馈区 | 使用 `{components.status-notice.background}` 承载当前问题。提交确认、查询错误、监测异常、取消请求和执行结果分别说明各自影响，短暂提示消失后仍可在对应状态区查到可确认的任务结果。 |
| 任务表 | 仅显示本人条目。任务名为可直接打开详情的链接，行内显示状态、队位（适用时）、原因和确认入队时间。显存未知可与任务名同组展示。表格字段到此为止，提交配置在本人详情中查看。FR-03、FR-08 / AC-01、AC-11、NFR-02。 |
| 任务状态区 | 使用 `{components.status-label.background}` 辅助识别当前状态。等待原因、上次确认、核对提示和取消反馈各有文字。详情与列表采用相同状态语义。 |
| 操作按钮 | 「提交任务」「刷新状态」「取消排队」用动作命名。`[ASSUMPTION]` 取消入口放在详情。普通刷新只读。取消结果未知时，详情点「核对取消请求」打开确认框。恢复入口以同一份完整快照的证据为准。 |
| 取消核对确认框 | **AI 代理取舍，待人工评审。** 从详情的「核对取消请求」打开。「返回详情」和「关闭」均不发送核对命令，只有「继续核对」发送。完整文案见下方候选。 |
| 取消确认框 | `[ASSUMPTION]` 显示任务名及「启动确认前可取消」。按钮为「返回详情」与「确认取消」。发送时可在按钮上反馈本次操作的进度。两页的任务状态按核对结果显示。FR-07 / AC-07、AC-09、AC-10。 |
| 任务配置 | 详情在所有权成立时显示自己的提交配置。若支持显示命令、工作目录或日志，均须按权限提供。仅本人可读取任务和获授权的私有输出。未登录及资源不可访问两类页面候选见 Q5，拒绝响应不携带目标任务信息。FR-01、FR-08 / AC-11、NFR-02。 |

## State Patterns · 状态与反馈

### 任务状态

| 用户可见状态 | 队位和反馈 | 取消排队 |
| --- | --- | --- |
| 排队中 | 已知位置显示「第 N 位」，并显示当前等待原因。GPU 监测异常作为等待原因，在队位能确认时可同时展示。 | 本人且仍符合取消条件时可发起。 |
| 已获准 | 领取与租约已提交，清除当前队位。显示「等待启动确认」，只有已提交的启动确认可进入运行中。 | 启动确认前仍可申请取消。竞态以服务端启动确认与取消确认的事务提交先后裁决。 |
| 运行中 | 模拟启动确认与启动事件同一提交后，显示本人的运行状态。后续观测到期不撤销已提交的启动。 | 取消排队截止。 |
| 已完成 | 已核实本次执行结束且不再用卡后，完成状态与释放同一提交。 | 无取消排队入口。 |
| 失败 | 已核实本次执行结束且不再用卡后，失败状态与释放同一提交。OOM 保留原参数，本人详情显示失败诊断。 | 无取消排队入口。 |
| 已取消 | 列表和详情在确认取消事务成功提交后显示「已取消」。任务退出队列。 | 无取消排队入口。 |

### 与任务状态并存的反馈

| 情形 | 展示与转移 |
| --- | --- |
| 监测异常：任务仍排队 | 显示具体监测原因。派发暂停。普通 GPU 占用有单独文案。 |
| 监测异常：任务已获准且未通过启动确认 | 显示监测原因并说明暂不能确认启动。保持最新已提交状态，启动证据未知时显示待核对。观测恢复后按最新有效观测及原排队顺序重新评估派发，失效的旧领取仍不可启动。FR-04 / AC-04、AC-05、AC-14、AC-15，AD-5、AD-6。 |
| 从未发起取消，启动状态待核对 | 两页均显示「启动状态待核对」。仅有启动待核对的证据时，也使用此文案。 |
| 已发起取消且取消结果未确认，启动状态待核对 | 两页均显示「启动状态待核对，取消尚未确认」。必须有已发起取消的证据。详情提供刷新；取消结果未知时也可主动核对。 |
| 启动待核对期间的资源提示 | 有监测异常时另行说明。即使 GPU 监测恢复，核实前也不得重新启动原任务或将其 GPU 派给其他任务。其他排队任务只见通用等待原因，例如「暂时没有已确认可派发的 GPU」。FR-04、FR-05、FR-07 / AC-07、AC-08、AC-14、NFR-01。 |
| 启动已提交，随后观测到期 | 已确认仍执行时保持「运行中」。若展示监测提示，说明影响后续派发与未确认启动。FR-04、FR-05 / AC-14，AD-4、AD-5 / Story 4.1。 |
| 已确认启动，执行状态待核对 | 显示「执行状态待核对」。保留已确认的启动事实与取消截止。结束证据确认后才采用已提交终态。FR-05、FR-06 / AC-03、AC-08，AD-6。 |
| 取消请求处理中 | 服务端已确认受理且尚无终局时显示「取消请求处理中」。详情状态区只提供刷新。 |
| 已确认取消事务成功提交 | 两页显示「已取消」，详情撤下取消按钮。晚到的旧回队反馈不得覆盖已确认的取消结果。 |
| 已核实未通过启动确认、未实际启动且未取消，回队事务已成功提交 | 两页显示「排队中」。回队沿用原入队顺序。两页显示服务端读取的当前队位与等待原因。回队事务提交前维持已确认状态。FR-02、FR-03、FR-04 / AC-13 至 AC-15。 |
| 启动确认事务先成功提交，取消被拒 | 两页反馈「已过取消截止点」，详情撤下取消入口。任务状态继续按已确认的执行信息更新。FR-07 / AC-07、AC-09、AC-10。 |

### 页面读取与提交反馈

| 页面 | 加载、空态和错误 |
| --- | --- |
| 提交任务 | 已登录时可填写。GPU 监测异常时派发暂停，任务仍可提交并等待。`[ASSUMPTION]` 发送期间显示「正在提交」并暂时禁用按钮。收到入队确认后才显示「已入队」；明确拒绝时给出反馈；响应中断时显示「暂未确认提交结果」，默认提供只读的「查看我的任务」。原提交重试见 Q6。 |
| 我的任务 | 首次显示「正在加载我的任务」。确认空列表后显示「还没有任务」和提交入口。查询失败时显示「暂时无法刷新任务状态」。同一已授权会话中已有的本人状态、队位和等待原因标为「上次确认」。首次失败时保留重试入口。 |
| 任务详情 | 加载期间先显示通用提示，确认访问权限后才显示数据。刷新失败时显示「暂时无法刷新任务状态」，已有本人状态、队位和等待原因标为「上次确认」。恢复取消入口须从同一份合格的完整快照确认旧请求已封存或终结，以及当前可取消。失去访问权限时撤去任务数据和动作。 |
| 所有页面 | 候选为未登录或会话失效时显示「请登录后继续」。两类访问拒绝回复均省略他人的任务及私有数据，详情见 Q5。FR-01、FR-08 / AC-11、NFR-02。 |

### 访问保护与页面候选

**服务端约束。** 所有权由可信会话确定，所属组由服务端映射。列表只返回本人任务，详情、取消和私有输出都检查所有权。同组关系、已知任务 ID 和客户端声明的身份都不授予访问权。未认证请求被拒，已登录访问他人任务与未知任务使用一致的资源不可访问响应。FR-01、FR-08 / AC-11、NFR-02，AD-7 / Story 1.3。

**界面候选 · AI 代理取舍。** 未登录或会话失效时，三页显示通用提示「请登录后继续」。此时不展示原页面的任务或私有配置。已登录但无权访问详情，或任务不存在时，页面统一显示「无法查看此任务」及「返回我的任务」。两类回复均不含他人任务或私有数据，也不透露目标任务是否存在。登录提示和拒绝页文案待人工确认。

| 文档走查 | 页面与服务端预期 |
| --- | --- |
| 匿名或会话失效后打开已知任务 ID | 仅显示通用登录提示，任务状态、路径、命令、环境变量、日志和私有标记均不可见。 |
| 同组非本人、异组用户打开已知任务 ID，或改用不存在的 ID | 已登录的三种详情请求得到相同的「无法查看此任务」。本人列表不包含他人任务，访问私有输出或尝试取消也无泄露、无状态变更。 |
| 本人用可信会话查询合成任务 | 本人列表有自己的任务，详情及授权输出可读到本人的合成私有标记。符合取消条件时仍可取消。 |

负向用例兼顾伪造所有者或组字段，预期越权成功数、标记泄露数、未经授权的状态变更数均为 0。这里只走查文档，运行验收待执行。

### 提交重试合同与页面候选

**服务端约束。** AD-2 以事务提交确认入队。Story 1.1 下，同一可信所有者以同一原提交键重试完全相同的内容，返回原任务和原入队序号，队列仍只有一条记录。同键异内容被拒绝，原任务不变。FR-01、FR-02、FR-08 / AC-01、AC-11、NFR-02，AD-2、AD-7 / Story 1.1。

**界面候选 · AI 代理取舍。** 提交结果未知时显示「暂未确认提交结果」，默认提供只读的「查看我的任务」。如果服务端已确认入队，本人列表可读到该任务。尚未看到任务或无法确认它对应本次提交时，继续保留未确认反馈。

| 已知条件 | 页面候选 |
| --- | --- |
| 同一可信所有者、同一原提交键和完全相同的原内容均可确认 | 可提供「重试原提交」，只由本人主动触发，复用原提交键和原内容。 |
| 原提交键或原内容无法确认，或无法确认仍为同一可信所有者 | 保留「暂未确认提交结果」与只读入口，省略「重试原提交」。 |
| 用户要修改内容 | 走独立新提交，使用新提交键。发出前提示「前一次提交仍可能已入队」。由本人再次确认提交，无自动发起。 |
| 服务端拒绝同键异内容 | 提示「内容已变更，请发起新提交」。原任务保持原样，重新填写和提交由本人决定。 |

模拟首版按 Story 1.1 使用任务名、作为任务数据的执行命令，以及「未知」或以 GiB 表示的正数显存估计。显存未知可提交。选择填写估计时，空值或非正数显示字段反馈。跨页或重开时无需缓存私有命令来恢复原提交；无法确认原内容时遵循上表的未确认分支。

**文档走查。** 首次提交成功但回执丢失时保留未确认提示；用相同所有者、原键和原内容手动重试，返回原任务且不重复入队；同键异内容被拒；缺原键或原内容时只有只读核对和独立新提交路径；若已入队，本人列表能看到该任务。运行验收待执行。

### 取消核对与入口恢复

列表和详情在同一登录会话内关联同一个待核对取消请求，切页、刷新或重开后继续核对原请求。列表提供状态与详情链接，操作放在详情。启动也待核对且有取消请求时，可合写「启动状态待核对，取消尚未确认」。仅启动待核对时沿用短提示。

| 服务端证据 | 用户看到的反馈 | 详情动作 |
| --- | --- | --- |
| 请求超时、查无记录或无法核实 | 「取消结果尚未确认」。已知任务状态照常显示。 | 保留「刷新状态」，另提供「核对取消请求」以打开确认框。取消入口关闭。 |
| 已确认受理，尚无终局 | 「取消请求处理中」。 | 只提供「刷新状态」。确认后若发现受理已先提交且尚无终局，也进入此分支。原请求继续处理，取消入口关闭；已有终局时按已确认结果展示。 |
| 主动核对后确认旧请求已封存，或已确认旧请求有终局结果 | 封存可提示「上一次取消请求已停止处理」。若本次确认未取消，按已确认任务状态展示。 | 只有同一份合格的完整快照同时证明当前待核对的确切请求已封存或已终结，且任务仍可取消，才恢复「取消排队」。 |
| 确认取消已经成功提交 | 「已取消」。 | 撤下「取消排队」，状态随完整快照更新。 |
| 确认已过取消截止点 | 「已过取消截止点」。 | 撤下「取消排队」。任务状态按完整快照显示。 |

普通「刷新状态」只读，不封存请求、不自动重发。详情只在本人点击确认框的「继续核对」后发送主动核对命令。服务端在与受理互斥的事务内核对并持久封存未受理的旧请求。若核对结果仍未知，保留核对反馈和刷新，仍不恢复取消入口。恢复后，由用户再次确认取消，系统使用新请求 ID，界面省略 ID 和内部事务。FR-05、FR-07 / AC-07、AC-10、NFR-01，D-010 / AD-4 / Story 3.1–3.3。

### 核对确认框候选

**AI 代理取舍，待人工评审。** 详情在取消结果未知时保留「刷新状态」，点击「核对取消请求」先打开确认框。说明文案如下。

> 如果上一次取消请求尚未受理，继续核对会阻止它之后生效。已经受理的请求会继续处理。

操作为「返回详情」和「继续核对」。打开确认框、返回、关闭或按 Escape 都只改变界面，不写入、不发送核对命令。只有「继续核对」才发送主动核对命令。若旧请求在此之前已受理，服务端不封存，原请求继续处理。若尚无终局，显示「取消请求处理中」，取消入口关闭，仅保留只读刷新。已有终局时按 D-010、D-011 的完整快照规则反馈。

### 取消超时的文档验收

1. 让原取消请求在服务端受理前超时。两页普通刷新或重开时继续核对同一请求，查无记录仍显示未知，入口保持关闭。打开确认框后分别用「返回详情」和关闭退出，核对均未发送命令。重新打开并点「继续核对」才发送；若受理先提交且无终局，显示「取消请求处理中」，旧请求继续处理，取消入口保持关闭。已有终局时按已确认结果展示，两种情况都不封存已受理请求。
2. 让主动核对先持久封存旧请求，取得同时确认封存和仍可取消的完整快照，详情恢复取消入口。用户尚未发出新请求时，放行迟到的旧请求并重放，断言任务、原租约及其历史、取消记录、取消事件和快照版本均无变化。
3. 用户手动再点取消，使用新请求 ID。若仍符合取消条件，取消和租约释放各成功一次。若最新完整快照已确认不可取消，即使旧请求已结束也不恢复入口。FR-05、FR-07 / AC-07、AC-10、NFR-01，D-010 / AD-4 / Story 3.1–3.3。

## Interaction Primitives · 操作

- 「刷新状态」、重开和浏览器返回均按共享的页面更新规则读取。读失败时已有画面标「上次确认」。
- 启动确认与取消确认以服务端事务先成功提交的一方为准。

### 两页共享的页面更新规则

- 同一登录会话内，两页共享已见的服务端快照版本下限。任务状态、当前全局队位、等待原因和取消资格取自同一份已提交的完整页面快照。版本与入队序号独立，前序任务离队或只有等待原因变化时版本也会更新。界面省略版本号。
- 刷新、切页和重开时，采用不低于下限的完整快照。两页可分别采用相同版本的完整响应。缺少可比较版本或低于下限的响应不更新页面及操作。旧画面仍可见时标「上次确认」，取消入口不可由旧画面恢复。
- 仅含取消结果的回执按请求关联，只更新该请求的已确认反馈，不能覆盖整页、清空其他列表行或启用取消。旧请求的回执不能解除新请求的待核对。若回执提高了版本下限，两页低版本缓存均标「上次确认」，重新读取达到下限的完整快照后更新页面。FR-02、FR-03、FR-04、FR-07 / AC-02、AC-07、AC-13、AC-14，D-011 / AD-2 / Story 1.2、3.2、4.2。

## Accessibility Floor · 无障碍底线

- 键盘顺序跟随页面阅读顺序，焦点用 `{colors.focus}` 标出。表单错误聚焦首个无效字段，字段与错误说明关联；选择「未知」时可跳过数值输入。提交成功或结果未知时聚焦对应反馈标题，可继续 Tab 到「查看我的任务」。
- 确认框打开时聚焦「返回详情」，Escape 退出尚未提交的确认。关闭后回到发起控件，控件已撤下时回到任务状态区。
- 从提交结果进入列表时聚焦「我的任务」标题，从本人任务链接进入详情时聚焦详情标题。返回列表时优先回到原任务链接，若已不可见则聚焦列表标题。刷新时焦点留在「刷新状态」。如果当前聚焦动作因新状态被撤下，焦点回到本人的任务状态区标题。
- 当前页用礼貌播报区（`role="status"`）提示已采纳快照带来的实质变化，例如「第 1 位」「GPU 观测数据已过期」「已获准」「运行中」「已完成」或「失败，GPU 显存不足」。状态、队位和原因同次变化可合并一条。相同内容、未采纳的旧快照和非本人数据均不播报。刷新失败时提示「上次确认」。
- 缩放或长文案使内容折行时，保留标签、状态、动作和完整原因。视觉焦点和对比度目标见 [DESIGN.md](DESIGN.md#colors--色彩)。

## Key Flows · 场景走查

以下是合成示例。A 属于林妍，B 属于另一组的周宁，每人只在自己的会话中看到自己的任务。

### UJ-01 等卡并获得结果

1. 合成账号林妍在「提交任务」选择显存「未知」，以合成任务数据提交 A。另组的合成账号周宁提交 B。两卡忙时，各自从「我的任务」进入自己的详情，分别看到第 1、2 位及「GPU 正被占用」，A 仍标为「未知」。丢失 A 的入队回执时，默认只读查看本人列表，符合原提交重试条件时才手动重试。
2. 测试设施演示一种监测异常及恢复，两页显示对应的已确认等待原因。观测恢复后，在领取尚未提交时，任务仍按返回的排队状态显示。有效观测只确认一张卡可用时，系统先领取队首 A。林妍看到「已获准」，周宁看到自己的 B 仍排队、队位由 2 变 1。三个异常分支及切换可用卡各用独立用例验证。
3. **核对点。** 林妍在「任务详情」看到 A 从「已获准」到「运行中」，仅依据已提交的启动状态。分别从运行中推进正常完成和模拟 OOM 两条独立用例。林妍分别看到「已完成」或「失败 · GPU 显存不足」，后者的本人诊断说明原任务参数已保留。

测试设施使用独立的合成会话、模拟观测、权威模拟时钟、事务暂停点和模拟执行替身安排顺序。任务页面只提供提交、本人查询和已授权的操作。注入监测故障、选卡、推进时钟、驱动领取、启动、完成或 OOM 等演示步骤由测试设施执行。
