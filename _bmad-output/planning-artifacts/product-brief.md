# LabQueue 产品简报草稿

这是依据已有用户陈述、课程要求与四人分工方案整理的工作草稿。用户已确认首版范围和四项验收条件。`bmad-product-brief` 仍在进行，团队评审尚未完成，课程 M1/M2 尚未通过，验收结果待验证。

## 问题与目标用户

**已确认的使用场景**　目标使用者是共用一台双 L20 服务器的研究生，来自不同研究组。需要考虑平台外使用和首次任务显存需求未知的情况。

**一次真实排队经历**　用户原计划在晚上跑一组实验，通过 SSH 登录后用 `nvidia-smi` 看到两张卡都在使用。群里无人能给出大致的空闲时间，用户只能隔一会儿再登录查看，也无法确定卡空出来时会不会被别人先用上。实验直到第二天才启动，原计划当晚拿到的结果随之推迟。

**待验证的问题**　实际使用人数、类似等待和冲突的频率、其他用户的协调方式，以及他们受到的影响。

**建议方案：**为愿意接入的研究生提供一个提交、查询、取消和解释等待原因的入口。平台按可观测的资源状态保守准入；监测失效或外部占用看不清时暂停新的真实派发。普通用户权限无法阻止平台外任务，也不能承诺全服务器独占或固定等待时长。

## 四周首版范围

课程规定四周、两轮 Sprint，功能实施须通过 M1/M2 后开始。用户确认模拟闭环是四周验收必达项，真实 L20 派发是条件目标。作业仅通过 GitHub 仓库交付。不汇报、不录屏、不做实验 B，保留实验 A。

| 层级 | 首版内容 | 通过条件或边界 |
| --- | --- | --- |
| 必做：任务入口 | 可信身份下提交、查询和取消本人任务，展示本人的排队位置和等待原因，以及排队、获准、运行、完成、失败、监测不可用等状态 | 后端校验任务所有权；他人命令、路径和日志不可见；身份来源待架构确定 |
| 必做：保守准入 | 两张 GPU 以稳定标识管理；事务性领取与租约保证同一卡至多一个**平台**任务；未知显存任务可申请整卡平台使用权 | 取消、重试和崩溃并发不得重复启动；监测失效、过期或外部占用不明时停止新真实派发；用模拟资源源先做可重复验收 |
| 必做：模拟闭环 | 使用模拟资源完成提交、排队、派发和完成或失败的状态反馈，覆盖取消和监测异常路径 | 在 GitHub 提供可复现的模拟验收证据。M4 提交测试证据并明确标注为模拟 |
| 条件目标：真实 L20 派发 | 在真实 L20 上以提交者自己的执行身份启动一个受控任务 | 先经架构评审及服务器验证，确认提交者的执行身份、外部占用可见性、启动与取消确认及故障恢复 |

**已确认的排队规则**

- 跨研究组采用全局 FIFO。按系统实际确认入队的先后排序，入队序号持久化。墙钟回拨、时间相同和服务重启均不改变确认顺序。依据 D-003、FR-02。
- 本人可在启动确认成功前取消排队，包括已领取但尚未通过启动确认的任务。取消先成功时，任务进入已取消，启动次数为 0，已有租约解除。启动确认先成功时，取消排队请求被拒绝。依据 D-002、FR-07。

**建议延期：**组权重与复杂组间轮转、组内用户轮转、使用统计报表、完整审计分析、同卡多任务显存拼装和自动显存预测。首版全局 FIFO 无组间公平保证。

## 首版验收硬门槛

以下四项必须在模拟环境中全部验证通过。验收时记录模拟条件、预期结果与实际观察。当前四项均待验证。

| 验收项 | 通过条件 |
| --- | --- |
| 排队可见 | 两张模拟卡均被占用，两名用户分别提交任务，各自能看到自己的排队位置和等待原因。释放一张卡后，按首版排序规则轮到的任务获准，用户能看到最终状态。 |
| 异常时暂停派发 | 模拟监测失效、数据过期或因权限不足等原因无法确认外部占用时，新增派发次数为 0，用户能看到阻塞原因。监测恢复后，以最新有效观测重新判断。 |
| 并发时避免重复启动 | 在并发领取、取消和重试用例中，同一卡同时最多有一个有效平台租约，同一任务最多产生一次模拟启动事件。 |
| 取消与权限 | 用户能在启动确认成功前取消本人的任务，含已领取的任务。取消先成功时启动次数为 0，已有租约解除。越权查询、取消或读取他人私有任务信息的成功次数为 0。 |

队列查询性能仍是候选 NFR，阈值、并发量、数据量和测试环境待确定，当前没有基线。

## 建议的关键设计问题

- 外部进程可在“检测空闲”与“启动任务”之间抢占 GPU。普通权限下只能重新检测、谨慎启动并处理冲突，无法消除竞态。
- 若研究生有不同 Linux 账户，需考虑每用户代理或用户主动执行。普通账户的中心服务无法代替所有人切换身份。
- 未知显存任务初次申请整卡的平台使用权，实际运行时记录采样峰值。模型、输入、batch、精度等改变后旧记录不再直接用于准入。
- 组间轮转及按 GPU 时间记账属于后续公平策略，需要真实用户反馈与 PRD 取舍。
