## 意图

双卡模拟目前只为队列查询提供固定占用数据。为两张固定 UUID 的模拟卡建立持久准入状态，用可控时钟和故障注入验证 FR-03、FR-04、AC-04、AC-05、AD-1、AD-5。本人列表和详情显示同一已提交版本的等待原因。

## 范围与约束

采集开始时记录模拟时钟与采集顺序。服务启动或更换发布者时先关闭准入并推进代际。接收新样本前处理上一份观测的到期。观测、过期、准入代际及等待原因变更所需的页面版本在同一 SQLite 写事务中更新。

本轮交付候选卡判定与本人查询。任务领取、租约迁移、启动和真实 GPU 监测属于后续工作。

## 场景

| 给定 | 当 | 则 |
| --- | --- | --- |
| 队列非空、GPU 1 可用 | 查询失败或少报任一卡 | 候选为空，显示监测失败 |
| 两卡都已报告 | 任一卡外部占用不明 | 候选为空，显示占用不明 |
| 快照有效 | 模拟时钟先推进到截止点前，再推进到截止点 | 截止点前仍准入。达到截止点后候选为空，显示过期，代际同步递增。回拨、重复推进或读取均不重复使快照失效 |
| GPU 1 曾可用，随后观测故障 | 新有效快照中仅 GPU 2 可用 | 只允许 GPU 2；重放旧序号或旧发布者样本后保持该结果 |
| 原数据库有排队任务 | 服务重启后尚无新观测 | 准入关闭，保留任务和队位；已提交过期状态可在重启前从新连接读回 |

## Implementation Notes

- 使用固定的 30 模拟秒有效期，从采集开始计算。模拟控制入口仅在应用进程内提供。无观测时两卡均不可准入，页面显示监测失败。
- Python 场景从新 SQLite 连接核对候选卡、时钟、代际与版本。本人的列表和详情同时核对队位与原因。页面用例验证迟到响应无法覆盖已显示的故障或恢复结果。
