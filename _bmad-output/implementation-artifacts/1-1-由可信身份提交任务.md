# Story 1.1：由可信身份提交任务

## 实施状态

本故事与 Sprint 跟踪均为 `done`。Astra 提出的四项问题已修复，独立复审在 Windows 本地模拟范围内未发现阻塞项。人工页面走查已记录，最后一项迟到查询提示也已修复并通过回归。

## Intent

作为提交者，我可以用自己的身份登记任务，即使显存需求未知也能排队。提交回执丢失时，我可以核对或重试原提交，而不会重复入队。

**依据**：[Epic 1](../planning-artifacts/epics.md#story-11--由可信身份提交任务) · [PRD](../planning-artifacts/PRD.md) · [架构](../planning-artifacts/architecture.md) · [项目上下文](../project-context.md) · [UX 交互说明](../planning-artifacts/ux-designs/ux-LabQueue-2026-11-19/EXPERIENCE.md)。追溯：FR-01、FR-02、FR-08；NFR-02；AD-1、AD-2、AD-7；AC-01、AC-11。

## 实施范围

- 使用合成账号。任务所有者和组来自服务端可信会话及组映射，不由表单或请求字段决定。浏览器 Cookie 写请求遵循项目的跨站请求校验规则。
- 按已确认的范围提交任务名、仅作数据保存的命令，以及未知或以 GiB 表示的正数显存估计。用同一写事务持久化任务、分配唯一入队序号，并按 AD-2 推进影响页面的快照版本；仅在提交成功后确认入队。
- 用提交键识别同一用户的同一次提交。重复请求只在所有者、原键和内容一致时返回原任务；提交结果不明时先允许只读核对，不自动重发。
- 不实现队位展示（1.2）、完整的列表与私有输出隔离验收（1.3）、监测、GPU 派发、执行或取消。不运行用户提交的命令，不连接真实 L20。

## 验收条件

| 场景 | 必须观察到的结果 |
| --- | --- |
| 已认证用户在双模拟卡忙的场景中提交未知显存任务 | 持久化一条排队任务，显存仍为未知，分配唯一入队序号。服务端记录的所有者和组与可信会话及映射一致；本人可核对提交结果。无需实现监测或派发来构造此场景。 |
| 匿名提交，或客户端试图声明其他所有者或组 | 匿名提交不新增任务。客户端字段不授予权限，也不能使任务归属其他人或组。 |
| 首次提交已成功，但回执丢失；本人用原提交键与相同内容重试 | 返回原任务和原入队序号；只存在一条任务记录，不发生第二次入队。同一所有者以原键提交不同内容时拒绝请求，原任务不变。 |
| 选用显存数值，但字段为空或非正数 | 页面提示对应字段问题，不确认入队；选择未知时不要求填数值。具体提示和手动重试入口沿用 UX 候选，待人工复核。 |

## Implementation Notes

### 2026-11-25 · Astra 复审修复与取证

| 发现 | 修复及验证 |
| --- | --- |
| SQLite 文件可被其他本机用户访问 | 默认库已移入运行账号私有目录。在本机 Windows 的默认目录及真实主库、WAL、SHM 上用 `icacls` 回读，允许项仅有所有者、SYSTEM 和 Administrators。回归测试分别给临时目录、主库、WAL、SHM 增加普通用户读取权限，四种情况下启动均被拒绝。上轮浏览器测试留下的空库已逐字节核对后迁入同一私有目录。Linux 分支检查账号所有权及权限位，本次实测平台为 Windows。 |
| 确认回执随后被超时覆盖 | 页面以原提交键关联正在等待的请求。真实 Chrome 中延迟已提交的 POST 回执，先用 GET 核对成功，再等满 12 秒触发浏览器超时。页面仍显示原任务已确认，重试入口保持关闭。 |
| 切换账号后旧页可能展示另一人的回执 | 浏览器核对时同时提交页面所属会话的凭证。真实 Chrome 两个标签页共用 Cookie，A、B 各自持有同键的不同任务。B 页显示自己的回执，A 旧页收到 403 并提示刷新，未出现 B 的任务编号。 |
| 高精度 JSON 小数经浮点转换后被判为相同 | 提交路由按原始数字直接解析为十进制数。API 回归验证同键先提交 `1.00000000000000000001`，改为 `1.00000000000000000002` 返回 409，原值末尾补零仍返回原回执，序号和版本均只推进一次。 |

使用合成数据在本地回环地址完成真实浏览器走查，浏览器为 Chrome 158.0.8127.37（无头模式）。`uv run --locked pytest -q` 通过 24 项，保留一条 TestClient 的依赖弃用警告。`node --test tests/submission_page.test.cjs` 通过 7 项，启动检查与 Ruff 均通过。

### 初次实现记录（复审修复前）

- 本次验证基于 `2ef22b0ed16ce312511426aa028431a5a5a4cf89` 上的本地工作区改动。测试用账号和命令均为合成数据。

- SQLite 在同一写事务内登记任务、入队序号和快照版本。服务端按所有者、原提交键及内容判定重放。浏览器仅在本标签页保留待核对的键，当前页仍有原内容时才可手动重试。

- `node --test tests/submission_page.test.cjs` 通过 5 项，覆盖回执超时、只读核对及手动重试、刷新恢复原键、丢弃过时反馈、禁用浏览器存储、显存字段反馈。使用模拟 DOM；浏览器工具未能打开页面，实际浏览器走查待复核。
- `uv run --no-cache --locked python scripts/check_env.py` 与 `uv run --no-cache --locked ruff check .` 均通过。证据范围为 Story 1.1 及其适用的 AC-01、AC-11 子集，完整 NFR-02 验收留给后续 Story。
