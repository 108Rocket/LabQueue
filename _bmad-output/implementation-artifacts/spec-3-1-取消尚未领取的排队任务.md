## 意图

提交者能从本人详情撤回尚未领取的排队任务。服务端提交取消后，本人列表与详情显示「已取消」，后续任务按原入队序号前移。

## 边界

仅在本地双卡模拟使用合成账号。复用可信会话、CSRF、SQLite 写事务和全局快照版本。已领取任务的取消与启动竞争归 Story 3.2。交付为本地提交，Sprint 停在 review。

## 验收情景

| 给定 | 当 | 则 |
| --- | --- | --- |
| 两卡均忙，A、B 依次排队 | 本人取消 A，重放原 ID，再使一张卡可用 | A 只出队一次，新增领取和启动均为 0。B 队位从 2 到 1，领取该卡 |
| 旧 ID 尚未受理 | 普通刷新，再由本人主动封存，重启后放行并重放旧请求 | 刷新保持未知且零写入。迟到请求保持封存后的任务、请求、租约、事件和版本。本人手动使用新 ID 才取消 |
| 原 ID 受理已提交，尚无终局 | 停服，用原库启动新服务 | 服务端复核当前证据，符合条件时用原 ID 完成一次取消。只有一条请求和一个终局 |
| 他人已知任务和请求 ID | 同组、跨组合成账号尝试取消或封存 | 与不存在的任务得到相同反馈，持久状态不变。匿名及无效 CSRF 拒绝 |
| 列表和详情有较旧排队画面 | 完整快照、取消回执及旧响应乱序抵达 | 仅完整已提交快照更新状态与队位。匹配 ID 的局部回执可提高共享版本下限，不能恢复入口或替换任务行 |

- `src/labqueue/submissions.py` 的 `owns_task`、`_task_snapshot` 与 `initialize` 分别提供事务内归属校验、同版本读取和旧库初始化。
- `src/labqueue/app.py` 的 `lifespan` 与 `require_csrf` 提供恢复时机和写入口。领取、启动与租约历史沿用 Epic 2 的模拟入口。
- `src/labqueue/static/tasks.js` 的 `withVersionFloor` 协调同会话跨页版本，`taskCard` 展示列表及详情。

## 实现记录

取消成功的持久证据采用原请求行上的 `cancelled` 终局及其 `resolved_version`。该行在任务退出队列的同一事务更新，跨重启可按所有者、任务和原 ID 查回。若裁决时已有领取，记录 `ineligible`，任务和租约继续沿用已有状态。

| 构建复查来源 | 判定 | 依据与处理范围 |
| --- | --- | --- |
| 盲审 · 取消确认 | 中 | 初次及封存后的新取消直接发送 POST，补任务名确认。 |
| 盲审 · 暂时性裁决失败 | 中 | 已受理后发生临时数据库错误可停在处理中，复用服务端恢复入口继续处理。 |
| 盲审 · 标识规范化 | 低 | 列表按原字符串核对，详情按 UUID 核对，统一验证和规范化。 |
| 盲审 · 已终结 ID 累积 | 中 | 完成或失败的任务可能继续携带封存或未能取消的旧 ID，按完整快照清理。 |
| 盲审 · 回执落后于共享版本 | 中 | 匹配原 ID 的回执到达时，其他任务可能已推进版本，详情仍需读取当前快照。 |
| 盲审 · 已知终局遇到写锁 | 中 | 已封存或已终结的重放可直接读取 WAL 中已提交的不可变结果。 |
| 盲审 · 列表逐任务核对 | 低 | 每个排队任务额外执行资格查询，大列表读取增加往返。将资格判断并入快照查询。 |
| 盲审 · 写入竞争覆盖 | 中 | 顺序重放无法证明两个在途命令的先后裁决，补受理与封存重叠的测试。 |
| 盲审 · 退出确认框 | 低 | 原夹具总是同意确认，补返回时的零写入断言。 |
| 边界复查 · 服务运行期间恢复 | 中 | 两次写事务之间出错的原 ID 需由服务端继续处理，与盲审中的恢复项一并验证。 |
| 边界复查 · 完整响应所带 ID 已过时 | 中 | 拒绝响应内容之前仍须记录已见版本，防止更低版本响应恢复旧队位或入口。 |
| 边界复查 · 过时回执的只读刷新 | 中 | 同一 ID 的合法回执即使版本较低，也需触发只读 GET。 |
| 边界复查 · 已结束任务的查询参数 | 中 | 已确认终局和永久不可取消的任务可清理其待核对键。 |
| 验证缺口 · 关闭封存确认 | 低 | 检查同一 ID、页面状态及发送次数，覆盖主动放弃封存。 |
| 验证缺口 · 其他已打开标签页 | 中 | 手动刷新与重开无法覆盖浏览器存储事件，另测旧详情自动禁用和只读核对。 |
| 验证缺口 · COMMIT 回执丢失 | 中 | 在提交点分别制造已提交及未提交的异常，从独立连接核对终局、队列和版本。 |
