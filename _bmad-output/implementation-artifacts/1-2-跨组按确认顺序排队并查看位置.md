## Intent

本人从任务列表和详情查看当前全局队位及等待原因。独立验收使用固定双卡占用数据。跨组排序以已提交的入队序号为准。

## Boundaries & Constraints

- 复用 Story 1.1 的可信会话、持久序号与幂等登记。查询只返回本人数据。读取版本、队位和原因使用同一 SQLite 已提交快照。
- 普通刷新只读。真实监测、派发和取消均在范围外。释放单卡后的领取归 Story 2.2 联调。前序离队和等待原因变化由测试事务构造。

## I/O & Edge-Case Matrix

| 给定 | 当 | 则 |
| --- | --- | --- |
| 双卡忙、A 与 B 属于不同组 | 同时刻提交或墙钟回拨后提交，回执可以逆序 | 序号按提交顺序，A、B 各只见本人队位 1、2 和 GPU 占用原因 |
| 原队列持久化 | 重建服务，再确认 C | 原序号和队位保留，C 获更大序号及队位 3 |
| 读快照已建立 | 前序离队与原因变化提交，再放行读取 | 两个端点各返回完整旧快照，下次查询才同时读到新版本、队位和原因 |
| 新快照先到 | 旧响应晚到，或切页、刷新、重开后收到旧响应 | 保留新队位和原因。低于共享下限的旧缓存仅标「上次确认」。缺版本或非完整快照不可采用 |
| 队位不变 | 只改变等待原因，旧响应后到 | 版本推进且显示新原因，取消入口始终不可用 |

</frozen-after-approval>

## Code Map

- `src/labqueue/submissions.py` 已有 WAL、同步写与持久计数器。保留历史回执契约。复用连接与版本计数，先建立读取快照，再取本人任务及前序全局计数。新增模拟输入须兼容已有库并保持版本。状态或原因变更的测试事务也需同提交推进版本。
- `src/labqueue/app.py` 复用会话及页面凭证校验。详情对他人和不存在的任务给同一结果。`templates/index.html` 与 `static/submission.js` 有登录壳、导航、请求函数和超时，可复用。
- 前端按会话保存共享版本下限，持久区只需保存版本。用十进制字符串和精确比较。并发页面写下限须串行，读取失败时已有数据标为上次确认。浏览器返回须复查版本。
- `tests/test_submissions.py` 有合成账号、临时私有库和并发连接示例。`tests/submission_page.test.cjs` 有可控响应的 VM 测试。

## Implementation Notes

独立验收及 Windows 本地人工验收均已通过，Sprint 状态为 `done`。追溯范围为 FR-02、FR-03、AD-1、AD-2、D-011 与 AC-13 的独立验收部分。单卡释放后的实际领取留待 Story 2.2 联调。

- 固定双卡数据只在 SQLite 首次建立模拟表时写入，升级保留原任务、提交回执与计数器。列表先计算全局队位，再筛出本人的任务。详情沿相同排序规则统计前序任务。读取事务固定版本后再读任务和占用事实。
- 列表和详情共用一个登录会话的版本下限。浏览器本地存储只记版本，Web Locks 负责让同会话各页面依次比较和保存。普通刷新只读。独立验收用测试事务模拟前序离队及等待原因变化。
- 用户在另一标签页退出或切换账号后，旧标签页会在查询收到会话拒绝时清除数据。跨标签即时清理见 [Story 1.3 待联调项](deferred-work.md)。
